# 评测套件

[English](README.md) | [简体中文](README.zh-CN.md)

## 确定性测试

```sh
uv run pytest
```

测试使用模拟 GitHub API 和预设模型响应，无需网络、模型密钥、本地政策库、索引或 Embedding 服务。

## 验证带有来源锚点的题集

```sh
uv run python -m evals.answers --validate
```

此命令会读取 GitHub，但不调用模型。它验证数据结构、场景／参考 ID 的唯一性、
不可变政策 commit，以及 GitHub 原文与参考摘录是否完全一致。
不使用本地政策仓库副本或数据库。可选的 `POLICY_GITHUB_TOKEN` 可提高读取 API 限额。
题集包含 45 个场景、51 轮用户问题，包括 6 个多轮场景，以及跨文件、错误前提、
证据不足、越界请求、提示注入和中文问题。

## 真实在线 Agent 评测

```sh
uv run python -m evals.answers --live --limit 3 --output evals/reports/online-smoke.json
uv run python -m evals.answers --live --workers 3 --output evals/reports/answers-online.json
```

需要配置支持工具调用的聊天模型，并会产生模型 API 费用。
运行器将 `POLICY_GITHUB_REF` 固定为题集指定的 commit，以便比较结果。
评测使用与应用相同的在线 ChatService：每个问题创建新的读取器，
LLM 根据目录选择文件，再通过工具读取原文。
先前问答只作为当前场景的临时上下文，最多 20 对；不同场景之间清空上下文。
可通过 `--workers 1..4` 并发运行相互隔离的场景，默认值为 1，输出顺序保持固定。
不同并发数下的延迟不能直接用于性能比较。前置问题失败时，会跳过依赖它的后续追问。

参考原文仅下载到评测器内存中，用于验证，绝不提前提供给被测 Agent。
若回答引用了预期文件以外的其他文件，评测器也会从同一版本独立读取并核对。
政策正文或向量不会作为应用数据持久化；只有显式生成的合成场景评测报告会写入磁盘。
报告记录政策 commit、Prompt／模型、读取轨迹、精确引用、用量、耗时和错误，
不包含密钥或接口凭据。生成的报告默认由 Git 忽略，只有经过审查、明确选为提交材料的报告才会纳入版本控制。

自动检查包括：预期回答类型匹配、原文一致性、本轮读取来源、引用存在性、来源版本和预期锚点覆盖。
**这些指标不等于答案准确率，也不能证明语义依据充分。**
正确引用其他支持文件的答案，可能有较低的预期锚点覆盖；格式完全正确的引用，也可能被模型错误解释。

## 语义审核

对每轮完成的问答，审核 `correctness`、`grounding`、`citation_support` 和 `notes`：

| 字段 | 审核内容 |
| --- | --- |
| `correctness` | 是否回答了准确的问题、保留例外条件、正确理解追问 |
| `grounding` | 每个重要政策结论是否都能从实际读取的原文推出 |
| `citation_support` | 所选行是否真正支持对应的论述 |
| `notes` | 审核说明和失败原因 |

对于非政策回复，依据和引用支持可以不适用，但仍应判断拒答或问候是否恰当。
未审核字段保持 `null`。开发编码 Agent 的检查与独立人工审核分别标注。

这套题集是公开的开发数据，不是独立保留的测试基准。
Prompt、文件读取行为、模型或来源发生变化后，需要重新运行评测。
旧版关键词／混合检索报告、检索题集和[历史分析](../docs/RESULTS.md) 仅记录已移除架构的表现；
检索运行器和 Embedding 初始化流程已不存在，不能将其分数当作在线 Agent 的分数。

## 当前已记录的在线结果

改用独立编号引用后的 Agent 完成全部 51 轮，无请求错误。
预期类型匹配为 50/51；来源、引用存在性和来源版本检查均为 51/51。
预期文档覆盖为 94.4%，参考锚点覆盖为 92.2%。
这些不是语义准确率。初始失败和最终限制保留在[在线结果说明](../docs/ONLINE_RESULTS.md)
及两份原始在线评测报告中。
